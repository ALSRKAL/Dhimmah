## What closes it

On a Mac with Xcode 16 or newer, from the repository root:

```bash
# 1. Boot a 6.9-inch simulator (the size App Store Connect asks for)
xcrun simctl list devices | grep -i "iPhone 16 Pro Max"
xcrun simctl boot "iPhone 16 Pro Max"
open -a Simulator

# 2. Capture Arabic (Yemeni riyal) and English (US dollar)
flutter drive --driver=test_driver/integration_test.dart \
  --target=integration_test/store_capture_test.dart \
  -d "iPhone 16 Pro Max" --keep-app-running \
  --dart-define=STORE_LANG=ar --dart-define=STORE_THEME=light \
  --dart-define=STORE_CURRENCY=yer

flutter drive --driver=test_driver/integration_test.dart \
  --target=integration_test/store_capture_test.dart \
  -d "iPhone 16 Pro Max" --keep-app-running \
  --dart-define=STORE_LANG=en --dart-define=STORE_THEME=light \
  --dart-define=STORE_CURRENCY=usd

# 3. Pull the frames out of the simulator's app container
xcrun simctl get_app_container booted com.dhimmah.dhimmah data
#   → <container>/Documents/store_capture/ar|en/*.png

# 4. Compose and validate the same way Android was
#    (point the compositor at the iPhone captures, canvas 1320 × 2868)
python3 tool/store_capture/compose_assets.py
python3 tool/validate_store_assets.py
```

The capture test itself is device-independent: it seeds the same ledger, walks
the same eight screens and applies the same language/theme/currency assertions on
iOS as it does on Android. Only the runtime is missing, not the harness.
